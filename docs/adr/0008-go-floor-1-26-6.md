# ADR-0008: The Go floor is 1.26.6, inherited from `moat/redisstore`

## Status
Accepted — 2026-09-29

## Context
`moat/redisstore v0.2.2` declares `go 1.26.6`. It reaches `crypto/tls` (through
`go-redis`) and `encoding/asn1` (certificate parsing on a TLS connection),
which carry GO-2026-6090 and GO-2026-5972, fixed in 1.25.13 and 1.26.6.

## Decision
usher's `go.mod` declares `go 1.26.6`, stated as a full patch version, and CI
builds and tests at that version. `govulncheck` runs on the newest supported
toolchain, since a scan against a standard library that no longer receives
fixes reports findings no change here can resolve.

## The alternative that was rejected
**`go 1.25.13`**, which looks like the more conservative floor. Go orders
versions across release lines, so 1.26.5 satisfies a floor of 1.25.13 — and
1.26.5 has neither fix. Only 1.26.6 covers both lines.

## Consequences
- This is an application, not a library: the floor is an imposition inherited
  from a dependency, not a promise to importers, and raising it costs nothing
  downstream.
- The floor moves when a dependency's does, or when a standard-library fix on a
  reachable path requires it. The move is a new ADR or an amendment here.

## Amendment — the floor moves to 1.27.2 for GO-2026-6617 (#139)

The Consequences above say the floor moves "when a standard-library fix on a
reachable path requires it". GO-2026-6617 (CVE-2026-97032, an HTTP/2 server
crash in `net/http`, published 2026-10-08) is that case: affected are stdlib
< 1.26.9 and 1.27.0–1.27.1, and CI's `govulncheck` traced it through the
gateway's `RoundTrip`, the JWKS fetch and the resource server's `http.Server`.

**Decision:** the floor is **1.27.2**, and CI and both images build with it.

**Why not 1.26.9**, which is the smaller step: it is this ADR's own original
argument, one release later. Go orders versions across lines, so a `go 1.26.9`
floor is satisfied by 1.27.0 and 1.27.1, which carry no fix — exactly as a
1.25.13 floor would have been satisfied by 1.26.5. Only 1.27.2 excludes every
vulnerable version.

**What it cost:** build, vet and the race-enabled suite were green on 1.27.2
unchanged. golangci-lint had to move from v2.12.2 to v2.14.0 (the former is
built with Go 1.26 and refuses a newer standard library); its one new finding,
`ReverseProxy.Director` deprecated, was a real bug in its own right (#137).

**Exposure, so nobody overstates it:** the crash is server-side HTTP/2, and
neither binary serves TLS or h2c today, so with TLS terminated in front of
usher (REQUIREMENTS §1.1) the path was not exercisable. The floor moves anyway,
because a floor that depends on a deployment assumption is not a floor.

**Recorded because it was not resolved:** a local `govulncheck` v1.8.0 did not
reproduce CI's finding with any toolchain tried (1.26.6, 1.26.9, 1.27.1, 1.27.2;
darwin and linux; a freshly downloaded `vulndb.zip` containing the entry). The
move rests on the advisory itself and on CI's run, not on a local scan.
